# Variable Cleaner

Figma-плагин для диагностики ссылок на коллекции и снятия явных назначений режимов в выделении или на текущей странице, включая вложенные и скрытые слои экземпляров.

## Установка

В Figma Desktop: **Plugins → Development → Import plugin from manifest…** и выберите `plugin-variable-cleaner/manifest.json`.

## Использование

1. Выделите компоненты, экземпляры или фреймы и оставьте область **Выделенные объекты**. Для обработки страницы выберите **Текущая страница** — проверяется сама страница и все её вложенные слои.
2. Нажмите **Проверить**. Раздел **Что удерживает коллекции** покажет переменные, их коллекции и режимы, а также слои и свойства, где сохранились ссылки. Раскройте переменную, чтобы увидеть путь к слою; **Приблизить слой** показывает его на холсте. Другие страницы не загружаются и не проверяются.
3. В разделе **Что удерживает коллекции** отметьте старые версии по ID и списку режимов. Недоступные переменные можно выбрать отдельно.
4. Нажмите **Отвязать выбранные коллекции…**. Появится план с количеством свойств и слоёв и ошибками подготовки. Подготовка ничего не изменяет.
5. Нажмите **Отвязать**. Выбранные привязки заменятся конкретными значениями. После операции выполняется повторная проверка оставшихся ссылок и назначений.

### Автоматическая перепривязка при конфликте

Если отчёт нашёл несколько ID у одного ключа коллекции, в разделе **Перепривязать версии** выберите старую и актуальную версии. Плагин сопоставляет переменные сначала по одинаковому ключу и типу, затем по точному имени и типу. Кандидатов он берёт из всей выбранной актуальной коллекции, включая пока не использованные в проверенной области. Нажмите **Подготовить перепривязку…**, изучите пары переменных и пропуски, затем **Перепривязать**.

Заменяются прямые привязки свойств слоёв, заливок, обводок, эффектов, сеток, текстовых диапазонов и свойств компонентов. Если на слое есть связанный стиль, его связь на этом слое может быть снята; общий стиль не изменяется. Переменные, на которые ведёт цепочка из другого токена, и привязки внутри общих стилей показываются в пропусках. При неоднозначном или отсутствующем совпадении ссылка сохраняется. После полной перепривязки явно назначенный режим старой версии переносится на режим с таким же именем в актуальной коллекции; если совпадения нет, старое назначение остаётся.

В конце плагин повторно проверяет область и сообщает, сколько старых ссылок и назначений осталось. Если результат не равен нулю, проверьте перечисленные пропуски или используйте отвязку для оставшихся ссылок.

Обрабатываются все вложенные слои выбранной области, включая скрытые слои экземпляров. Плагин не определяет автоматически, какая версия удалена или актуальна: нужные версии выбираются вручную.

Отвязка включает ссылки через цепочки переменных: отвязывается свойство слоя, использующее токен. Библиотечные переменные, коллекции и общие стили не редактируются и не удаляются. Другие коллекции остаются привязанными.

Поддерживаются доступные привязки свойств слоя, заливок, обводок, градиентных остановок, эффектов, сеток, текстовых диапазонов и свойств компонентов. Для связанных стилей при необходимости снимается связь со стилем на обрабатываемом слое. Шрифты текста загружаются перед изменением. Для недоступной переменной используется сохранённое значение свойства, если оно доступно.

Неподдерживаемые или недоступные свойства остаются в отчёте; нулевой счётчик при частичной проверке не означает полной очистки. Привязки, доступные только через текстовый стиль, могут требовать отдельной обработки. Результат следует проверить визуально.

Выбранные явные назначения режимов снимаются после успешной отвязки, если повторная проверка полная и не осталось привязок выбранных коллекций. Если объект коллекции недоступен, API может не позволить снять явное назначение — оно остаётся с объяснением ошибки. Источники компонентов и родители вне выбранной области не изменяются: их унаследованные связи могут оставаться видимыми.

Отдельный раздел **Явные назначения режимов** позволяет снять режимы без отвязки переменных. После этого слой наследует режим родителя или использует режим по умолчанию, что может изменить внешний вид.

После изменения выделения или страницы выполните проверку заново. Свойства, изменившиеся после подготовки плана, пропускаются. Для отмены используйте Undo в Figma.

## Как читается диагностика

- **Конфликт версий:** у одной коллекции совпадает библиотечный ключ, но разные ID. Для каждой версии показаны её режимы, переменные и слои. Одинаковые имена коллекций с разными ключами не считаются конфликтом.
- **Ссылки через переменные и стили:** проверяются доступные привязки свойств, заливок, обводок, эффектов, сеток, текстовых диапазонов и используемых стилей. Ссылки между переменными прослеживаются по значениям всех режимов, а не только активного; путь указан в отчёте. Один слой, переменная и свойство считаются одной ссылкой, даже если она продублирована в данных заливки.
- **Недоступная переменная или коллекция:** ссылка сохранилась, но API не вернул объект. Это может быть удаление или ограничение доступа; плагин не выдаёт это за подтверждённое удаление.

Диагностика не импортирует и не обновляет библиотечные ресурсы. Она показывает, что удерживает коллекцию в проверенной области, но не сравнивает файл с последней публикацией библиотеки. Если найдена только одна старая версия, конфликта нескольких версий не будет — её режимы и слои всё равно появятся в отчёте. Отсутствие конфликтов не доказывает актуальность переменных. Источники компонентов вне выбранной области и назначения на внешних родителях не обходятся.

После изменения выделения или страницы нужно выполнить проверку заново. Очистка затрагивает выбранные ссылки и назначения из последнего отчёта внутри проверенной области.
