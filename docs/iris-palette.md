# Iris: светлая шкала

Шкала `iris100–700` пересобрана для светлых интерфейсов. `iris100` близок к
белому, первые ступени дают небольшие различия между подложками, а расстояния
между оттенками постепенно увеличиваются к акценту. `iris800–1300` сохранены.

| Примитив | Значение sRGB | Ориентир для применения |
| --- | --- | --- |
| iris100 | `#FAFAFF` | Почти белая подложка |
| iris200 | `#F6F6FF` | Мягкая подложка |
| iris300 | `#EAEAFF` | Светлый фон компонента |
| iris400 | `#D7D8FF` | Более выраженная подложка, hover |
| iris500 | `#BDBFFE` | Выраженная светлая заливка |
| iris600 | `#9F9FFB` | Переходный оттенок |
| iris700 | `#7D77F6` | Выразительный контур, переход к акценту |
| iris800 | `#5B40ED` | Существующий основной акцент |

Это ориентиры для выбора семантического токена, а не универсальная привязка
номера к состоянию. Например, `KidsLight.fill.solid.selected` сохраняет
iris800 и светлый текст. Светлые 100–500 рассчитаны на тёмный текст;
самостоятельные значимые границы и индикаторы проверяются отдельно.

## Построение

Использована OKLCH с нелинейной светлотой. Для `t = (номер / 100 − 1) / 7`
в диапазоне 100–800 целевая светлота равна
`L = 0.987 − (0.987 − L800) × t^1.9`.
Цветность растёт пропорционально `(1 − L) / (1 − L800)` относительно C800,
тон плавно переходит от 284.3° к тону существующего iris800 по `t²`.
Выход за sRGB устраняется уменьшением цветности при сохранении светлоты
и тона; затем значения округляются до HEX. Сам iris800 остаётся точным якорем.
Диапазон светлоты 100–500 сократился примерно на 36%.

Подход опирается на
[роли ступеней Radix Colors](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)
и [перцептивную модель Oklab](https://bottosson.github.io/posts/oklab/).
Конкретная кривая и распределение 13 примитивов выбраны для этой палитры;
они не являются стандартом Radix.

## Зависимые семантические значения

Новый iris700 с белым даёт 3.60:1, iris600 — 2.38:1. Поэтому заливки,
предназначенные для светлого текста, используют неизменённый iris800:

- KidsLight: светлый конец меню, обе точки continuum и конечная точка
  непрозрачного inverse-hover; составные градиенты и отдельные Step-токены
  обновлены вместе.
- Kids: `fill.solid.accent`, чтобы сохранить читаемость основного текста
  с белым 96%.

Минимальный контраст белого в этих градиентах KidsLight — 6.17:1;
для inverse-текста с непрозрачностью 96% — 5.82:1. В Kids основной текст
на accent даёт 5.82:1, inverse.primary на selected — 16.75:1.
Порог для обычного текста —
[4.5:1 по WCAG](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Остальные ссылки на светлые примитивы сохранены: в KidsLight подложки
100–400 станут светлее, в Kids выбранные элементы на iris300 и акцентный
текст на iris500 тоже посветлеют. `glassy` сохраняет существующую альфу
80% / 80% / 90%; его результат зависит от родительской поверхности
и не обязан совпадать с `solid`. Hover по-прежнему строится относительно
соответствующего Rest.

## Проверка

`python3 scripts/check_kidslight_contrast.py` проверяет ссылки, согласованность
градиентов, порядок светлых уровней, итоговые смеси, текст, границы и фокус.
`python3 scripts/check_inverse_hover.py` проверяет inverse-hover во всех темах.

Inverse-hover проходит проверку во всех четырёх темах. Общая проверка
KidsLight по-прежнему останавливается на существующей слабой
`glassy.inverse.fourth`: на белом фоне её контраст с inverse.primary равен
3.98:1, с secondary — 3.89:1, с third — 3.80:1. Эти три результата одинаковы
до и после изменения, поскольку iris1000 и альфа 65% сохранены. При полном
сравнении 42 проверок WCAG новых нарушений не найдено; прежнее нарушение
solid inverse-hover устранено. Порог 4.5:1 в проверке не ослаблялся.

Контрастные расчёты не заменяют визуальную проверку компонентов после
синхронизации в Figma. Тёмные Main и Meta не используют изменённые примитивы;
существующие ограничения их полупрозрачного inverse.third отмечаются проверкой.
